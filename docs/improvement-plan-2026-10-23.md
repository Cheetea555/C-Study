# C-Study 改进优化方案

> 历史方案：本文记录初次评估时的问题与建议，下文「当前」指评估时的源码快照。后续已交付记录见 [更新记录](../CHANGELOG.md)，包括记录保护、统一搜索、复习调度、全局计划、四科内容关联、完整备份和页面置换演示。
日期：2026-10-23。依据：当前本地 C-Study 与 `postgraduate-exam-website-master` 的源码、数据文件和测试，不以 README 的功能描述代替实现核查。

本文保留改造前的基线分析；首批已实施的功能、兼容规则和验收范围见 [首批改进记录](implementation-progress.md)。

## 1. 建议方向

建议将 C-Study 继续发展为「四科个人备考工作台」，重点补强知识内容、练习证据和复习任务的连接。

参考项目最值得借鉴的三点是：**稳定的知识内容标识、知识与历年真题的双向关联、可定位正文的统一搜索**。C-Study 已有计划、计时、错题间隔复习和本地记录，这些是继续扩展的基础。

近期优先级：

1. **P0：保护学习记录**，修复损坏数据回退、跨科导入和保存失败反馈。
2. **P0：稳定内容 ID，逐步抽取公共引擎**，为后续扩充内容建立基础。
3. **P1：用 408 的一个章节做闭环试点**，实现课程、知识点、题目、错题之间互相定位。
4. **P1：接入真题练习、四科统一搜索和基于作答记录的诊断**。
5. **P2：按学习需要补交互演示、排版和在线离线缓存**。

不建议在首轮实施中安排全站框架迁移、云账号体系或 AI 自动出题。这些并非当前主要缺口，也不是借鉴参考项目必须承担的成本。

## 2. 两个项目的实际差异

| 维度 | C-Study 当前实现 | 参考项目当前实现 | 对 C-Study 的启示 |
|---|---|---|---|
| 定位 | 数学二、408、英语二、政治的个人学习与记录 | 408 电子教材与真题阅读练习 | 保留四科工作台，借鉴教材与真题的组织方式 |

| 题目关联 | 题目归属章节，课程通过 `quiz` 引用题目 | 真题通过 `knowledgeBlockIds` 精确引用正文，支持反查 | 增加题目到知识点、课程及具体讲解的回链 |

| 教学展示 | 文字、折叠例题、自研简单数学标记 | 多类型内容块、Markdown、公式、图片、分步动画 | 补充难点演示与结构化正文，不必全站动画化 |
| 学习记录 | 本地持久化、计时、错题、课程状态、复习安排 | 已检查的真题作答组件与仓库方法主要负责当前答案反馈 | 参考项目不应被视为完整个人学习管理系统 |
| 测试 | 20 个科目测试脚本 + 1 个公共回归脚本 | 内容校验、Vitest 单元/组件测试、Playwright 页面测试 | 补数据迁移、内容语义和真实浏览器流程测试 |

## 3. P0：学习记录的可靠性

### 3.1 修复读取损坏记录后覆盖原数据

以 408 为例，`load()` 读取或解析失败后返回默认状态，`init()` 发现没有计划就生成计划并调用 `save()`。因此，损坏 JSON 会在启动过程中被默认数据覆盖，失去后续恢复原文的机会。

**实施建议：**

- 读取结果区分「首次使用」「正常旧数据」「损坏或不支持的数据」「存储不可用」。
- 解析失败时保留原键原文，禁止自动初始化写回；提供下载原始记录、尝试恢复、主动重置三个入口。
- 可在存储允许时保留一份最近有效快照；存储已满或不可访问时，仍能通过文件导出当前内存记录。
- `save()` 的返回值应传递到导入、计时归档、清空等操作的反馈，写入失败时明确显示「尚未保存」。

**验收：**用损坏 JSON 启动后，原始字符串不变；无法保存时不提示操作已持久化成功；恢复成功后课程、错题、计时记录仍可读取。

### 3.2 为备份增加科目和版本信息

当前 `importData()` 只做少量顶层结构检查，没有校验科目身份，也没有检查 `v` 的兼容性。用英语二的默认备份导入 408，当前代码会接受；模拟存储写入失败后，仍会出现「导入成功」。

建议新备份使用明确的信封结构：

```json
{
  "format": "c-study-backup",
  "schemaVersion": 2,
  "subjectId": "408",
  "contentVersion": "2026-10",
  "exportedAt": "2026-10-23T08:00:00.000Z",
  "data": {}
}
```

- 校验科目、支持的版本、日期、数值范围、数组元素结构和复习阶段。
- 新备份导错科目时拒绝；旧备份通过课程/章节/题目 ID 辅助识别，无法识别时让用户指定科目，不能静默猜测。
- 导入前展示科目、记录数量和覆盖范围，并提供当前数据的导出入口。
- 先在独立对象上完成校验和迁移，保存成功后再切换当前状态；失败时保留原状态。
- 新增「四科完整备份」：同源环境可汇总为一个 JSON。本地文件模式若无法读取其他科目，应提示备份不完整，并支持分别收集各科备份文件。

不应承诺 localStorage 的跨键事务。若后续采用 IndexedDB，可以再设计真正的事务式多科恢复；首版至少做到逐科校验、失败回滚和清晰结果报告。

### 3.3 处理多标签页覆盖

当前总览监听了 `storage` 事件，但科目应用仍将整份内存状态写回同一个键。两页同时打开同一科目时，旧页写入可能覆盖另一页的新记录。

首版增加 `revision` 与页面实例标识：检测到外部更新后提示刷新/重新载入，防止旧状态直接写回。该方案降低覆盖风险，但不是严格并发事务；如需同时编辑，应引入事件记录合并或 IndexedDB 事务。

**修改入口：**四科 `app.js` 的 `load()`、`save()`、`importData()`，以及公共存储模块。先在 408 实现，再以同一兼容规则推广四科。

## 4. P0：稳定内容标识并抽取公共引擎

### 4.1 考点使用稳定 ID

当前课程的 `pts: [0, 1]` 引用章节考点数组下标，学习记录也以 `章节ID-下标` 作为键。往数组中间插入或重排考点，会让旧进度和课程引用指向另一个概念。

建议将考点改为显式对象，例如：

```js
{ id: '408.ds.linear-list.sequential-insert', title: '顺序表插入的移动元素分析' }
```

课程、题目和卡片通过 `pointIds` 引用它。显示顺序单独决定，重排不改变 ID；需要删除或拆分时保留迁移映射和废弃标记。

**迁移要求：**在更改数组顺序前，保存当前「旧键 → 新 ID」映射；覆盖四科并验证幂等性。已有记录升级时保留原始备份，未知旧键列入恢复报告，不能直接丢弃。存储键不必随 schema 升级改名，以免旧记录看起来消失。

### 4.2 公共界面之外，继续抽取业务引擎

四个 `app.js` 分别约 59—67 KiB，都包含日期、计划、状态存取、作答、错题、课程、计时和渲染。当前 `assets/workspace.js` 已共享界面，但核心业务仍分散在四份文件中。

建议渐进形成以下边界，具体文件数可随实现调整：

| 模块 | 职责 |
|---|---|
| `assets/core/storage.js` | 读取、校验、迁移、保存、导入导出 |
| `assets/core/planner.js` | 日期、章节计划、预算与任务编排 |
| `assets/core/practice.js` | 作答事件、判分策略、题集状态 |
| `assets/core/review.js` | 错题归档、复习调度、复发处理 |
| `assets/core/content.js` | 内容注册、按 ID 查询、反向关联 |
| 科目配置与数据文件 | 满分、目标、题型规则、章节、课程和题库 |
| `assets/workspace.js` 与各页面渲染 | 导航、展示、交互和可访问性 |

继续使用兼容经典 `<script>` 的模块封装，保留 file:// 直接打开的路径。先抽纯函数和存储，再抽作答与复习，最后处理渲染。不同科目的数学排版、满分和题型差异应作为配置/策略保留，不能用字符串替换批量统一。

**验收：**同一处调度修复只改一个公共实现；四科旧备份、现有测试、课程跳转和离线入口全部保持可用。

## 5. P1：知识点—课程—题目—错题双向连接

这是最值得从参考项目吸收的产品能力。

当前已有「课程 → 配套题 → 返回本课」，但题目只有章节归属，无法普遍定位具体知识点和讲解；错题反馈也很难直接转换为精准补课任务。

建议建立以下关系：

```mermaid
flowchart LR
  K[稳定 ID 的知识点] --> L[相关课程与讲解块]
  K --> Q[练习与历年真题]
  Q --> A[逐次作答记录]
  A --> M[错题与复习任务]
  M --> L
  L --> Q
```

首版只需补充 `pointIds`；当一课确实包含多个独立讲解时，再为正文块增加 `blockId`。无需一次性照搬参考项目的所有层级。

**使用流程示例：**

1. 用户做错一道链表插入题。
2. 解析展示「对应考点：指针修改顺序」，可直接进入相关课程的讲解位置。
3. 学完后进入该考点的其他练习，避免只记住刚刚见过的答案。
4. 错题本保留本次错选和解析快照，并安排复习。
5. 复习页可以返回当前版本课程；题目已修订时提示版本变化，历史记录继续保留。

建立自动反向索引：由题目的 `pointIds` 推导「知识点关联题」，由课程的 `pointIds` 推导「知识点关联课程」，不维护两套手写关联表。

**定位协议：**扩展当前 hash 导航，例如 `#learn?lesson=Lds02-2&point=...`，由统一解析器处理标签页、课程和考点。当前代码直接读取整个 hash 作为标签名，因此不能仅给现有链接追加参数。覆盖刷新、前进后退、无效 ID 和 file://。

**验收：**试点章节每道题都能回到相关讲解；从讲解进入相关题集后可返回原位置；多考点题在章节统计中按题 ID 去重。

## 6. P1：把真题成绩台账扩展为训练模块

### 6.1 分离题目来源与训练方式

当前 `renderPapers()` 展示人工录入的成绩和曲线。建议将现有页面标为「套卷成绩」，新增「真题练习」，二者共享套卷标识与成绩记录。

- 题目元数据：科目、来源类型、年份、卷别、题号、分值、题型、关联考点、内容版本。
- 来源信息：作者/出处、链接、授权说明、修订日期、审核状态；不把模拟题或改编题显示成原始真题。
- 单题训练与整卷模拟复用同一题源；整卷模式支持计时、暂存、交卷前隐藏解析。
- 主观题先提供分步评分点和自评，人工确认后写入成绩，区分自动分与自评分。

参考项目的「逐年原始试卷 → 自动汇总轻量索引 → 按需加载正文」值得采用，但 C-Study 的 file:// 路径应使用静态脚本内容包或预生成产物；不能直接照搬依赖 fetch 的 JSON 加载方式。

首批先整理少量经过核对的 408 真题并建立旧考点到新考点的映射，不把 846 道题直接复制进来当作已审核题库。参考数据的综合题可以解析为主、没有独立答案，转换器需要明确处理。

### 6.2 四科需要不同的题型能力

| 科目 | 主要缺口 | 建议第一步 |
|---|---|---|
| 数学二 | 150 题中只有 1 道 `solve`，解答训练占比小 | 增加计算/证明类题目及分步评分点；公式和解题步骤可清晰对照 |
| 408 | 现有题库没有 `solve`，难以检验综合解题 | 增加算法设计、地址变换、协议计算等综合训练，保留代码与推导 |
| 英语二 | 当前以独立选择题为主，缺少成组材料模型 | 增加「文章/材料 → 多个子题」，再补翻译与作文的自评量表 |
| 政治 | 48 题均为单选模型 | 先补多选，再增加材料分析及要点式自评；年度内容带适用年份 |

通用引擎可以支持 `singleChoice / multipleChoice / shortAnswer / composite`，每种题型单独定义评分策略。旧 `choice / fill / solve` 通过适配层兼容。材料题的文章只保存一份，子题引用材料 ID。

## 7. P1：统一搜索与可信的学习诊断

### 7.1 四科搜索

先覆盖课程标题/目标/正文、知识点、题干、解析和速查卡，提供科目与内容类型筛选。结果展示科目、章节、命中摘要和定位按钮。

当前只有 368 道练习，首版可以使用规范化文本、短语匹配、少量专业别名和字段权重，例如标题权重大于正文。为「PV / 信号量」「TLB / 快表」「导数 / 求导」建立可维护的别名表。

索引由内容自动生成，避免手工重复录入；可用 Node 工具生成并提交 `search-index.js`，最终用户仍直接打开 HTML。跨科搜索不必加载四科完整应用和学习记录，也不要默认将私人的错题笔记纳入公开索引。

当实际测量表明召回或耗时不足，再引入类似参考项目的分词、倒排索引或 MiniSearch。不能只凭「题库将来会大」增加运行负担。

**验收：**准备一组跨科固定查询，验证期望内容进入前列、摘要相关且能定位；检查无结果、英文缩写、手机输入和离线使用。

### 7.2 保存逐次作答，解释统计口径

当前 `recordAnswer()` 对每题保留最近对错、次数、日期和最后选项。统计页的正确率是「最近一次做对的题数 / 做过的题数」，无法还原首答正确率或全部尝试正确率。

新增只追加的作答事件：

```js
{
  id, questionId, contentVersion, sessionId,
  answeredAt, answer, correct, score, maxScore,
  mode, gradingMethod, durationSec
}
```

`mode` 区分首练、重做、复习、套卷；`gradingMethod` 区分自动与人工自评。未实现可靠计时前，耗时字段允许为空，不伪造精度。

- 保留现有 `qz` 作为快速汇总或兼容投影。
- 旧 `times` 只能继承为累计次数，不能凭空补出历史每次作答。
- 展示首次作答正确率、最近一段时间的表现和复习成功率，标注各自口径。
- 将手动「已掌握」与根据练习生成的「建议复习」分开，避免几道重复题就判定掌握。
- 自动错题当前默认原因为「原理没懂」，不能直接把它当作用户已确认的错误原因统计；应增加「未归因」状态和快速确认入口。

### 7.3 调整复发错题的安排

当前 `addQToMistake()` 对尚未掌握的重复错题只更新错解，不重排已有复习进度。因此，高阶段错题再次做错后，可能仍要等较长时间才出现在复习队列。

建议将「练习再次答错」作为独立复发事件，提前到下一次合适的复习窗口，同时避免同日重复点击造成多条任务。保留现有二档自评作为首版，后续再评估「不会 / 模糊 / 熟练」和间隔算法；有足够记录后才能判断复杂算法是否有收益。

## 8. P1：让四科计划符合实际时间预算

四科当前独立生成章节计划；默认每日目标分别为数学 240、408 240、英语 120、政治 90 分钟，相加为 690 分钟，即 11.5 小时。这是默认配置之和，不代表每位用户的实际安排。

`generatePlan()` 当前按考点数量把章节顺序分配到日期，再给章节窗口标记阶段；它没有为同一章节自动生成四轮复习任务。改进时应区分「阶段名称」和真正的「多轮任务」。

建议增加：

- 总览的全局每日可用时间、工作日/周末差异、休息日和科目分配。
- 先安排到期复习，再按预算安排新课与练习，为临时事项留余量。
- 根据课程预计时长和实际完成情况生成可执行任务；不足以覆盖时提示缺口和调整选项。
- 未完成任务顺延、合并或由用户舍弃，重排时不改变已完成历史。
- 按周调整后续负荷，并解释推荐原因，例如「该考点最近再次答错」。

首版采用明确规则和用户确认，不需要训练推荐模型。**验收：**四科任务预计时长不超过全局预算；休息日不安排新课；逾期任务有明确去向。

## 9. P2：教学展示、性能和离线体验

### 9.1 分步演示与排版

借鉴参考项目的分步播放器，优先选择 KMP、树遍历、页面置换、Cache 地址划分或滑动窗口中的两三个难点。用原生 SVG/Canvas 和状态表表达「上一步 / 下一步 / 重置」，支持用户先预测结果再揭示。

演示与知识点共享 ID；每个步骤有文字替代；支持键盘操作、减少动态效果和手机布局。算法正确性优先验证，不能只检查动画看起来顺畅。

数学排版当前只处理简单分数、矩阵和行列式。先补复杂表达式的降级展示与可读性。如果后续明确接受开发工具依赖，可在内容制作阶段用 KaTeX 预渲染并随站打包本地样式/字体；这会改变依赖说明，但不要求最终用户安装工具或联网。保持现有标记兼容，避免一次性重写全部内容。

### 9.2 先测量再优化加载

当前科目 HTML 一次加载全部数据脚本，`renderAll()` 同时渲染多个功能页。内容扩大后，优先改为首屏渲染当前功能、其他页首次进入时再渲染；章节正文按展开加载或生成局部 DOM。

HTTP 版可按科目/年份按需获取数据并缓存；file:// 版使用兼容的脚本内容包，或者保留完整离线包。两种路径应共享数据模型。

记录首次可操作时间、搜索耗时和页面 DOM 数量作为基线，再决定拆包。当前数量级尚不足以证明需要重型状态管理或复杂分包体系。

### 9.3 区分本地离线包与在线缓存

本地完整下载后打开 HTML，与线上访问后断网可用，是两项能力。当前仓库未见 Service Worker 注册，不能把浏览器普通缓存当作可靠的在线离线保证。

如果建设 PWA，将其作为 HTTPS/localhost 下的增强功能：缓存静态资源、提示离线包是否完整、提示新版本、避免学习过程中强制刷新。Service Worker 不用于 file://；更新静态缓存不能删除用户学习记录。首次使用尚未下载的内容，应明确显示不可离线访问。

跨设备同步可作为更后续的可选能力，先做好四科统一备份与恢复，再评估账号、冲突处理和同步服务。

## 10. 内容质量与测试改进

当前测试已能检查题目结构、章节覆盖、课程字段、配套题引用和数学标记，但结构合格不等于内容正确。

本次补充检查发现：政治认识论考点 `p04-1`「感性认识与理性认识」，未被该章两节课程的 `pts` 引用。这表示课程到考点的映射不完整，不等同于全文完全没有讲述这个概念。

建议内容校验增加：

- 稳定 ID 唯一、无悬空引用、废弃 ID 有迁移说明。
- 每个考点具备课程或独立讲解；缺少练习时显式列入覆盖报告。
- 课程配套题与考点匹配，不仅验证题目 ID 存在。
- 题型分布、题目来源、版本、审核状态和年度适用范围。
- 真实真题、改编题和自编题明确区分；借用内容记录作者、出处与对应授权信息。
- 重点公式、答案、解析和演示步骤由人工核对，修订后保留记录。

建议回归测试分三层：

1. **纯逻辑和数据：**复用公共实现测试，覆盖稳定 ID、反向索引、题型评分、预算和复习。
2. **持久化边界：**损坏 JSON、未知版本、跨科导入、存储写满、迁移幂等、保存失败、多页旧状态写回。
3. **浏览器流程：**课程 → 配套题 → 答错 → 回讲解 → 复习，套卷暂存恢复，导入导出，以及刷新/前进后退、窄屏和键盘操作。

浏览器自动化工具可以只作为开发依赖，不影响最终静态应用。当前 CI 的 `node --check *.js` 建议改为逐文件调用，以明确保证每个文件都被检查；本次已用逐文件方式完成检查。
